# انتشار دموی GitHub Pages

مقصد دمو: `https://mo90mosleh.github.io/SanaWebsite/`.

این پروژه مسیریابی hash دارد. دارایی‌ها با `assetPath` و مقدار Vite `BASE_URL` برای زیرمسیر مخزن resolve می‌شوند. فونت و ماسک لوگوی CSS نیز در build توسط Vite تنظیم می‌شوند؛ تغییری در نام دامنه سایت فعلی یا اتصال سرویس‌های واقعی داده نشده است.

## build و بررسی

```sh
npm ci --cache /tmp/sana-npm-cache --no-audit --no-fund
npm run test:pages
```

این دستور build مخصوص `/SanaWebsite/` می‌سازد و همان خروجی تولید را با مرورگر در زیرمسیر واقعی بررسی می‌کند: تصویر، فونت، کاتالوگ PDF، ورود مشتری، سفارش و پرداخت نمایشی، refresh، RTL و خطاهای HTTP/JavaScript.

برای build دامنه ریشه همچنان `npm run build` و برای توسعه `npm run dev` استفاده می‌شود.

## ارسال خروجی

```sh
npm run publish:pages
```

خروجی `dist` و فایل `.nojekyll` روی شاخه مستقل `gh-pages` قرار می‌گیرند. اسکریپت یک checkout موقت از شاخه انتشار می‌سازد؛ به فایل‌های checkout توسعه دست نمی‌زند، force-push نمی‌کند و در پایان پوشه موقت خودش را حذف می‌کند. شاخه موجود انتشار به‌روز می‌شود و در صورت یکسان بودن خروجی، commit تکراری نمی‌سازد. احراز هویت استاندارد Git لازم است؛ هیچ token یا secret داخل اسکریپت قرار ندارد. این دستور پس از تغییر کد باید دوباره اجرا شود؛ انتشار خودکار با هر push کد تنظیم نشده است.

## فعال‌سازی اولیه در GitHub

در مخزن `mo90mosleh/SanaWebsite` وارد **Settings → Pages** شوید:

1. بخش **Build and deployment**، گزینه **Source = Deploy from a branch**.
2. گزینه **Branch = gh-pages** و پوشه **/ (root)**.
3. دکمه **Save**.

اگر Pages قبلاً از همین شاخه فعال باشد، push خروجی آن را به‌روز می‌کند. در غیر این صورت، تا انجام این تنظیم اولیه صرف ارسال شاخه به معنی فعال بودن سایت نیست. اولین انتشار معمولاً چند دقیقه زمان می‌برد؛ وضعیت ساخت را در **Actions** و نشانی نهایی را در **Settings → Pages** بررسی کنید.

مخزن خصوصی ممکن است برای GitHub Pages به طرح واجد شرایط نیاز داشته باشد؛ خطای واقعی تنظیمات GitHub ملاک است. عمومی‌کردن مخزن خودکار انجام نمی‌شود.

این محیط به API مدیریتی GitHub Pages دسترسی ندارد و درخواست وب به دامنه github.io نیز با سیاست شبکه محدود است؛ فعال بودن لینک عمومی از داخل این محیط قابل تأیید نیست. هیچ‌کدام از این محدودیت‌ها با تغییر URL یا غیرفعال کردن TLS دور زده نمی‌شوند.

## داده دمو

پرداخت، پیامک و SERVICELOGS همچنان نمایشی هستند. داده‌های محلیِ نشانی توسعه به دامنه Pages منتقل نمی‌شوند. با اولین بازدید از دامنه جدید fixtures تازه ساخته می‌شود. هیچ اطلاعات واقعی مشتری وارد نکنید.

## بررسی پایان انتشار و ورودی تازه

ارسال `gh-pages` به‌تنهایی پایان انتشار نیست. `publish-pages.mjs` اکنون با `scripts/pages-status.mjs` فرایند عمومی **pages build and deployment** را در صفحات وب GitHub دنبال می‌کند و commit همان خروجی را با run تطبیق می‌دهد. فقط conclusion موفق برای همان SHA تأیید می‌شود؛ run شکست‌خورده یا timeout، موفقیت انتشار اعلام نمی‌کند. این بررسی از API مدیریتی یا دور زدن محدودیت github.io استفاده نمی‌کند. اگر ساختار صفحه عمومی GitHub تغییر کند، بررسی ممکن است نتواند وضعیت را بخواند و لازم است خروجی/Actions بررسی شود.

هر انتشار یک کپی HTML با نام `open-<source-commit>.html` می‌سازد؛ آدرس تازه، HTML قدیمیِ مسیر قبلی را از کش نمی‌گیرد. فایل‌های ورودی `open-*` قبلی حفظ و به نسخه جاری بازنویسی می‌شوند تا لینک قدیمی 404 نشود؛ این‌ها آرشیو نسخه‌های گذشته نیستند. دارایی‌ها همچنان از base `/SanaWebsite/` بارگیری می‌شوند. چون origin تغییر نمی‌کند، سفارش‌ها و بازخوردهای localStorage پاک یا منتقل نمی‌شوند. نیازی به پاک‌کردن داده مرورگر نیست.

بررسی واقعی run `41434084995` برای commit `b431ed42c8f40c30160133bf7fb9770917fccab3` موفق بود؛ GitHub آن را حدود ۴۶ ثانیه پس از شروع تکمیل کرده بود. فایل JS آن شاخه فاقد دکمه واسط و متن راهنمای قبلی و شامل ثبت مستقیم بود. مشاهده مستقیم HTML دامنه عمومی از محیط همچنان مسدود بود؛ تأیید run با مشاهده مستقل همه cacheهای کاربر یکسان نیست.

برای smoke test مسیر ورودی تازه پس از build: `PAGES_FRESH_ENTRY=1 node tests/pages-smoke.mjs`.
